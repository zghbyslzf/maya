# Maya CLI 项目优化方案

## 概述

本文档基于对 Maya CLI 项目完整源码的分析（8 个 crate + 5 个模块 + 集成测试），列出了实际存在的优化点。已完成的优化已移至"已完成"章节。


## ✅ 已完成

以下优化已在当前代码中实现：

| 优化项 | 说明 |
|--------|------|
| Clap 子命令架构 | `src/main.rs` 使用 `#[derive(Subcommand)]` 枚举分发 |
| 统一错误类型 | `maya_common::error::Error`（thiserror）+ `Result<T>` 别名 |
| 共享文件遍历 | `maya_common::file_utils`（`find_files`、`find_files_by_extension`、`find_by_name`） |
| 并行图片压缩 | `compress_pictures` 使用 rayon（`compress_images_parallel`，阈值 10 文件） |
| walkdir 替换递归 | `clear_node_modules`、`clear_lock` 等均已使用 walkdir |
| Clippy 警告 | 已修复（`is_some_and`、`flatten`、`&PathBuf`→`&Path`、移除冗余 use） |
| ImageType FromStr | 已实现 `std::str::FromStr` for `ImageType` |
| 单元测试 | `compress_pictures`、`clear_lock`、`mp4_to_m3u8` 已有测试 |
| 集成测试 | `tests/integration_tests.rs` 覆盖 help/version/参数校验 |
| 动态 FFmpeg 下载 | `mp4_to_m3u8` 通过 `ffmpeg-sidecar::auto_download()` 运行时下载 |


## 🔴 高优先级（代码质量问题）

### 任务 1：统一错误处理残留

当前 `git_add_commit_push` 和 `maya_common::lib.rs` 中的 `create_zip_archive` 仍使用 `std::io::Result`，未接入项目统一的 `maya_common::error::Result`。

**文件：**
- `crates/git_add_commit_push/src/lib.rs` — 函数签名返回 `io::Result<()>`，应改为 `maya_common::error::Result<()>`
- `crates/maya_common/src/lib.rs` — `create_zip_archive` 和 `format_result` 使用 `io::Result`

**方案：**
```rust
// git_add_commit_push/src/lib.rs - 修改前
pub fn git_add_commit_push(path: String) -> io::Result<()> {

// 修改后
use maya_common::error::{Error, Result};
pub fn git_add_commit_push(path: String) -> Result<()> {
    // ...
    Err(Error::command_execution("git add 失败"))
}
```

### 任务 2：`format_result` panic 问题

`maya_common/src/lib.rs:91` 的 `format_result` 在错误时直接 `panic!("操作失败")`，导致 CLI 在错误场景下 panic 而非优雅退出。

**方案：**
- 删除此函数（当前代码中似乎未被调用），或改为返回 `Result<T>` 让调用方处理。

### 任务 3：`maya_common::lib.rs` 与 `file_utils.rs` 功能重复

`lib.rs` 中有 `find_file(dir, filename)`，`file_utils.rs` 中有 `find_by_name(dir, name, MatchType::File)`，功能重叠。

**方案：**
- 将 `create_zip_archive` 移到 `file_utils.rs` 或独立模块
- `find_file` 改为调用 `find_by_name(dir, filename, MatchType::File)` 的简化包装

### 任务 4：硬编码路径分隔符（Windows 兼容性）

`crates/gitignore_add_zip/src/lib.rs:77` 使用硬编码 `/`：

```rust
if path.to_str().unwrap_or("").contains("/.git/")
    || path.to_str().unwrap_or("").starts_with(".git/")
```

Windows 下路径使用 `\`，该逻辑在 Windows 上无法正确跳过 `.git` 目录。

**方案：**
```rust
let git_dir = std::path::Component::Normal(".git".as_ref());
path.components().any(|c| c == git_dir)
```

### 任务 5：`compress_pictures` 代码重复

`compress_images` 和 `compress_images_parallel` 有 ~70% 重复代码（扩展名映射、类型提示文案、结果汇总逻辑）。

**方案：**
- 提取公共结果为 `CompressionResult` 结构体
- 将汇总打印逻辑提取为 `print_summary` 函数
- 让串行版本直接调用 `compress_images_parallel`（1 文件时 rayon 并不会有实质性开销）

### 任务 6：`git_add_commit_push` 错误处理不严谨

```rust
// crates/git_add_commit_push/src/lib.rs:33
if !commit_status.success() {
    println!("git commit 可能没有变更，无需提交");
}
```

`git commit` 失败原因有很多（冲突、pre-commit hook 失败、网络问题等），仅打印一行消息可能遗漏真正的错误。

**方案：**
- 捕获并检查 commit 的 stderr，区分"nothing to commit"（正常）与其他错误


## 🟡 中优先级（功能增强）

### 任务 7：压缩图片增加进度条

`compress_pictures` 目前仅逐文件打印日志，而 `mp4_to_m3u8` 有完整的 `indicatif` 进度条。

**方案：**
- 为 `compress_images` 和 `compress_images_parallel` 添加 `ProgressBar`，显示已处理/总数

### 任务 8：git 操作支持自定义 commit message

`git_add_commit_push` 硬编码 `"feat: update"`。

**方案：**
- 在 `Command::Git` 中添加可选的 `--message` / `-m` 参数
- `src/modules/git_ops.rs` 将 message 传递给 `git_add_commit_push`

### 任务 9：集成测试覆盖实际功能

当前集成测试仅覆盖 help/version/参数校验，未测试 pack、git、transform 等实际业务逻辑。

**方案：**
- `maya pack --type g` 测试（在含 `.gitignore` 的临时目录中）
- `maya clean --types lock` 测试（创建临时锁文件）
- 使用 `tempfile` 创建临时目录并验证结果


## 🔵 低优先级（依赖与构建）

### 任务 10：`compress_pictures` 依赖声明规范化

`crates/compress_pictures/Cargo.toml:11` 使用 `path = "../maya_common"`，其他 7 个 crate 均使用 `{ workspace = true }`。

**方案：**
```toml
# 修改前
maya_common = { path = "../maya_common", features = ["parallel"] }
# 修改后
maya_common = { workspace = true, features = ["parallel"] }
```
注意：修改后需确认编译通过（workspace 依赖应支持 feature 传递）。

### 任务 11：检查未使用的依赖

```bash
cargo +nightly udeps --all-targets
```

`maya_common` 的 `Cargo.toml` 声明了 `zip`、`regex`、`rayon` 等依赖，而实际使用这些依赖的 crate 可能自己声明了它们，存在 workspace 级别冗余声明的可能。

### 任务 12：README CLI 示例更新

`README.md` 中的示例（`maya -c n`、`maya -g m`、`maya -o all`）与当前 CLI 子命令格式不一致，实际用法为 `maya clean --types n`、`maya git --ops m`、`maya optimize --types all`。
