# Maya CLI 代码深度优化方案

## 概述

本文档基于对 Maya CLI 项目全部源文件的深度审查（8 个 crate + 5 个模块 + 集成测试），结合 Rust 官方最佳实践和各依赖库官方文档，列出了可优化的代码点。

## ✅ 已完成

以下优化已在当前代码中实现：

| 优化项 | 说明 |
|--------|------|
| 任务 1：Regex 缓存 | `vite_pack_add_zip` 三个正则使用 `std::sync::LazyLock` 静态缓存编译结果，并修复第三个正则 `s*` → `\s*` bug |

### 任务 1：Regex 每次调用重复编译

**文件**：`crates/vite_pack_add_zip/src/lib.rs:56,71,74`

**问题**：`get_out_dir` 函数中三个正则表达式每次调用都重新 `Regex::new()` 编译。正则编译（解析 + DFA 构建）是昂贵的操作。

**当前代码**：
```rust
fn get_out_dir(config_path: &Path) -> Option<String> {
    let re = regex::Regex::new(r#"(outDir\s*[:=]\s*['"]?)([^,'"}\s]+)['"]?"#).unwrap();
    // ...
    let build_block_re =
        regex::Regex::new(r#"(?s)build\s*:\s*\{.*?outDir\s*[:=]\s*['"]?([^'"},]+)"#).unwrap();
    // ...
    let m = regex::Regex::new(r#"outDir[=:]s*['"]?([^,'"}\s]+)['"]?"#).unwrap() ...
}
```

**优化方案**：使用 `std::sync::LazyLock`（Rust 1.80+ stable）缓存编译结果：
```rust
use std::sync::LazyLock;
use regex::Regex;

static OUT_DIR_RE: LazyLock<Regex> = LazyLock::new(|| {
    Regex::new(r#"(outDir\s*[:=]\s*['"]?)([^,'"}\s]+)['"]?"#).unwrap()
});
static BUILD_BLOCK_RE: LazyLock<Regex> = LazyLock::new(|| {
    Regex::new(r#"(?s)build\s*:\s*\{.*?outDir\s*[:=]\s*['"]?([^'"},]+)"#).unwrap()
});
static NESTED_OUT_DIR_RE: LazyLock<Regex> = LazyLock::new(|| {
    Regex::new(r#"outDir\s*[:=]\s*['"]?([^,'"}\s]+)['"]?"#).unwrap()
});
```
注意：第三个正则中 `s*` 应为 `\s*`（当前缺少反斜杠，匹配的是字面量 `s` 而非空白符）。

**影响范围**：`vite_pack_add_zip` crate，每次 Vite 打包可节省正则编译开销。

### 任务 2：FFmpeg 下载假进度条 JoinHandle 泄漏

**文件**：`crates/mp4_to_m3u8/src/lib.rs:188-199`

**问题**：`tokio::spawn` 返回的 `JoinHandle` 被立即丢弃，导致：
1. 假进度条任务脱离控制，即使下载已完成仍在后台运行（最多 5 秒）
2. 下载快于 5 秒时进度条可能只显示 30%；慢于 5 秒时停在 100%
3. 任务无法被取消（abort），存在资源泄漏

**当前代码**：
```rust
tokio::spawn({
    let pb = pb.clone();
    async move {
        for i in 0..=100 {
            pb.set_position(i);
            tokio::time::sleep(Duration::from_millis(50)).await;
            ...
        }
    }
});

let download_result = tokio::task::spawn_blocking(auto_download)
    .await
    .map_err(|e| ...)?;
```

**优化方案**：保存 `JoinHandle`，下载完成后调用 `.abort()` 取消假进度条任务：
```rust
let progress_handle = tokio::spawn({
    let pb = pb.clone();
    async move {
        for i in 0..=100 {
            pb.set_position(i);
            tokio::time::sleep(Duration::from_millis(50)).await;
            if i == 100 { break; }
        }
    }
});

let download_result = tokio::task::spawn_blocking(auto_download)
    .await
    .map_err(|e| Error::video_conversion(format!("FFmpeg下载任务失败: {}", e)))?;

progress_handle.abort(); // 无论成败都取消假进度条

match download_result {
    Ok(_) => {
        pb.finish_with_message("✅ FFmpeg下载完成");
        Ok(())
    }
    ...
}
```

**影响范围**：FFmpeg 首次自动下载体验。

### 任务 3：`create_zip_archive` 将整个文件读入内存

**文件**：`crates/maya_common/src/file_utils.rs:237-240`

**问题**：打包时将每个文件的全部内容读入 `Vec<u8>`，对于大文件（如打包中包含几十 MB 的 node_modules）会导致大量内存占用。

**当前代码**：
```rust
let mut f = fs::File::open(path)?;
let mut buffer = Vec::new();
f.read_to_end(&mut buffer)?;
zip.write_all(&buffer)?;
```

**优化方案**：使用固定大小栈缓冲区进行流式读取和写入：
```rust
let mut f = fs::File::open(path)?;
let mut buffer = [0u8; 8192];
loop {
    let n = f.read(&mut buffer)?;
    if n == 0 { break; }
    zip.write_all(&buffer[..n])?;
}
```

**影响范围**：所有通过 `create_zip_archive` 的打包操作（gitignore 打包、Vite 打包）。

### 任务 4：`gitignore_add_zip` O(n²) 线性搜索

**文件**：`crates/gitignore_add_zip/src/lib.rs:47-49`

**问题**：对 zip 中每个文件都在 `allowed_files` 的 `Vec<PathBuf>` 中做线性搜索。当文件数量较多时（例如 1000+ 文件），这是 O(n × m) 的比较量。

**当前代码**：
```rust
let zip_path = maya_common::create_zip_archive(source_dir, dest_path, |path| {
    path.is_file() && allowed_files.iter().any(|p| p == path)
})?;
```

**优化方案**：将 `allowed_files` 构建为 `HashSet<PathBuf>`，实现 O(1) 查找：
```rust
use std::collections::HashSet;

let mut allowed_files: HashSet<PathBuf> = HashSet::new();
for entry in walker.flatten() {
    let path = entry.path();
    if path.components().any(|c| c == std::path::Component::Normal(".git".as_ref())) {
        continue;
    }
    allowed_files.insert(path.to_path_buf());
}

let zip_path = maya_common::create_zip_archive(source_dir, dest_path, |path| {
    path.is_file() && allowed_files.contains(path)
})?;
```

**影响范围**：`gitignore_add_zip` 打包操作。

### 任务 5：`find_files_by_extension` 每个文件分配 String

**文件**：`crates/maya_common/src/file_utils.rs:88-91`

**问题**：`ext.to_lowercase()` 对遍历到的每个文件路径都分配一个新的 `String`，在大型目录中遍历数千文件时会引发数千次堆分配。

**当前代码**：
```rust
pub fn find_files_by_extension(dir: &Path, extensions: &[&str]) -> Result<Vec<PathBuf>> {
    let extension_set: std::collections::HashSet<&str> = extensions.iter().copied().collect();
    find_files(dir, |path| {
        path.extension()
            .and_then(|ext| ext.to_str())
            .map(|ext| extension_set.contains(&ext.to_lowercase().as_str()))
            .unwrap_or(false)
    })
}
```

**优化方案**：扩展名列表通常很短（最多 4 个），用大小写不敏感比较替代 HashSet + to_lowercase：
```rust
pub fn find_files_by_extension(dir: &Path, extensions: &[&str]) -> Result<Vec<PathBuf>> {
    find_files(dir, |path| {
        path.extension()
            .and_then(|ext| ext.to_str())
            .map(|ext| extensions.iter().any(|e| e.eq_ignore_ascii_case(ext)))
            .unwrap_or(false)
    })
}
```

**影响范围**：所有调用 `find_files_by_extension` 的操作（`compress_pictures`、`mp4_to_m3u8`）。

**问题**：`path` 参数使用 `String` 而非 `AsRef<Path>`，导致 `clean_ops.rs:10` 和 `git_ops.rs:8` 产生不必要的 `path.to_string_lossy().to_string()` 分配。

```rust
// 修改前
```

### 任务 7：`compress_images` 串行/并行两路行为相同

**文件**：`crates/compress_pictures/src/lib.rs:71-77`、`src/modules/optimize_ops.rs:38-44`

**问题**：`compress_images`（"串行"版本）直接委托给 `compress_images_parallel`，因此 `optimize_ops` 中的阈值分支实际两路都走并行。控制台输出"使用串行压缩"名不副实。

**当前代码**：
```rust
// compress_pictures/src/lib.rs

    compress_images_parallel(path, img_type, create_new_file)

// optimize_ops.rs
let (successful_compressions, failed_compressions, _avg_compression_ratio) = if file_count >= PARALLEL_THRESHOLD {

    println!("检测到 {} 个文件，使用串行压缩...", file_count);
    compress_pictures::compress_images(...)?
};
```

**优化方案**：统一保留并行版本，移除冗余的 API 和阈值逻辑：
```rust
// 删除 compress_images 函数，或改为真正的串行版本：
pub fn compress_images(...) -> Result<(u32, u32, f64)> {
    let extensions = extensions_for_type(&img_type);
    let image_files = find_files_by_extension(path, &extensions)?;
    // ... 使用 iter() 而非 par_iter()
}

// optimize_ops.rs 统一调用
compress_pictures::compress_images_parallel(path, img_type, create_new_file)?
```

**影响范围**：`compress_pictures`、`optimize_ops`。

### 任务 10：`remove_empty_dirs` 根目录检查不跨平台

**文件**：`crates/maya_common/src/file_utils.rs:186`

**问题**：硬编码 `"/"` 作为根目录判断，在 Windows 上根目录是 `"C:\"` 等形式，此检查无效。

**当前代码**：
```rust
if !has_content && dir != Path::new("") && dir != Path::new("/")
```

**优化方案**：使用 `Path::parent()` 判断：
```rust
if !has_content && dir.parent().is_some()
```

当 `dir` 为根目录时 `parent()` 返回 `None`，适用于所有平台。

**影响范围**：`remove_empty_dirs`，Windows 下避免尝试删除磁盘根目录。

### 任务 12：`parse_time_string` 静默吞非法输入

```rust
let hours: f64 = parts[0].parse()

let minutes: f64 = parts[1].parse()

let seconds: f64 = parts[2].parse()
```

同时更新 `test_parse_time_string_invalid` 测试中的预期行为（原测试期望非法输入返回 `Ok(0.0)`）。

**影响范围**：`mp4_to_m3u8`，进度显示准确性。

### 任务 20：`clear_lock_files` 中 `HashSet` 可静态缓存

**文件**：`crates/clear_lock/src/lib.rs:9`

**问题**：`lock_files` 是 3 个元素的固定集合，每次调用 `clear_lock_files` 都重新构建 `HashSet`。

```rust
static LOCK_FILES: LazyLock<HashSet<&str>> = LazyLock::new(|| {

});
```

**影响范围**：理论上可减少极小开销，实际无明显改善。

### 任务 21：`vite_pack_add_zip` 第三个正则存在潜在 bug

**文件**：`crates/vite_pack_add_zip/src/lib.rs:74`

**问题**：第三个正则 `r#"outDir[=:]s*['"]?...` 中 `s*` 缺少反斜杠，应为 `\s*`。当前 `s*` 匹配字面量 `s` 而非空白符，虽然大多数情况下不影响实际匹配结果（`[=:]` 后紧跟 `['"]?` 即可捕获常见写法），但不符合意图。

**当前代码**：
```rust
regex::Regex::new(r#"outDir[=:]s*['"]?([^,'"}\s]+)['"]?"#)
```

**修复**：改为 `\s*`：
```rust
regex::Regex::new(r#"outDir\s*[:=]\s*['"]?([^,'"}\s]+)['"]?"#)
```
建议与任务 1（Regex 缓存）一起修复。

**影响范围**：`vite_pack_add_zip`，Vite 配置解析正确性。
